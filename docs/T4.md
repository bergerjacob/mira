# T4: larger tasks, tooling fixes and verified physics facts (2026-11-02)

Context: five strong-agent (Sonnet-class) baselines solved `t2_door_2x2`, `t3_adder2` (raw and with lib), `t3_decoder2to4` and `t3_adder4`, mostly at the first `run_spec`, so T0-T3 no longer separate strong agents. This page records the harder tier built in response, the friction fixes, and what is and is not verified. Single source of the tasks: `env/tasks/author_t4.py`; commands at the end.

## Task table (4 tasks stored in `env/tasks/t4/`)

Every reference is a builder program over `lib/` parts (+ `wire_path` with `box/avoid/floor_exists/check_spacing`), compiled by `env/tasks/author_t4.py`; devices (levers, lamps) are fixed task scenery. "Gate" = `env/validate_tasks.evaluate` (spec valid and non-vacuous, reference reward exactly 1.0 with every invariant, empty build fails, >= 3 broken variants fail) plus the mutant kill rate (24 / 12 / 12 / 16 auto-mutants: remove / flip+turn / shift / delay / wire->stone). "Vanilla" = vanilla MC 26.2 GameTest oracle, **one JVM per capture** (`scripts/t4_oracle.py`), same stimulus/verdict machinery as `scripts/oracle_env_diff.py`.

| task | what | ref blocks / volume | in / out | behaviour | gate | kill | vanilla 26.2 | env run (ref) |
|---|---|---|---|---|---|---|---|---|
| `t4_addsub8` | 8-bit add/subtract with mode lever M (S = A + B or A - B mod 256; COUT = carry / no-borrow) | 1311 / 6240 | 17 / 9 | 12 corner rows + model stream (6 public, 40 hidden) | **ACCEPT**, 5 broken stored | 18/24 | **pass, tick-identical (1/1 capture, 42 vectors held 124 ticks)** | 23 s |
| `t4_adder16` | 16-bit ripple adder (+CIN) - the T3 adder body at 16 bits | 1993 / 9984 | 33 / 17 | corner rows + model stream | **ACCEPT**, 5 broken stored | 9/12 | **pass, tick-identical (1/1, 40 vectors held 220 ticks)** | 55 s |
| `t4_accum4` | 4-bit accumulator ACC := ACC + IN on every rising CLK edge (sequential, `d_flipflop` register, crossover for the clock tap, return row) | 861 / 6426 | 5 / 4 | 9 timed sequences generated from the python model (2 public) | **ACCEPT**, 5 broken stored | 10/16 | **pass, tick-identical (9/9 captures)** | 9 s |
| `t4_shift32` | 32-place serial-in/parallel-out shift register (chain of `d_flipflop`, clock bus runs against the data flow) | 962 / 1950 | 2 / 32 | 8 timed sequences (2 public) | **ACCEPT**, 5 broken stored | 9/12 | **NOT VERIFIED**: the isolated run was cancelled after 40 min (8 captures of 740-4800 ticks over a 333-block structure); no verdict either way. Env verdict only | 30 s |

Honest reading of the cells:
* "Accepted" means accepted by the env gate. The vanilla column is an independent check only where it says pass; `t4_shift32` has none and should be treated as Nucleation-only until `python scripts/t4_oracle.py t4_shift32` completes (needs about an hour; not tried with `--jobs 1`).
* The gate for `addsub8`/`accum4`/`shift32` ran before the validity agent's `block_in` change to `env/runner.py`/`env/contract.py`; that change only adds a region mode (none of the T4 ports use it) and the full test run afterwards passes the references (`tests/env/test_t4.py`).
* Survivors are the usual equivalent mutants (repeater delay +1, wire -> stone on a redundant cell); kill rates are lower bounds of spec strength, not coverage.
* `t4_adder16` is the T3 adder at twice the size: it measures scaling (routing consistency over 16 cells, ~2000 blocks), not new mechanics. `t4_addsub8` adds XOR gating of B and a mode bus (junction/tap repeater placement). `t4_accum4` and `t4_shift32` are the sequential tasks: they need a register (`d_flipflop`), clock distribution (the shift register's bus must run against the data direction or the data races through) and, for the accumulator, a crossover.

## Part A: friction fixes (each has a test)

| baseline complaint | fix | test |
|---|---|---|
| `full_adder` (and `half_adder`, `xor2`, `wire_link`) ignored `floor=False` and wrote y=0, which the task floor rejects | the y=0 support plane is only written with `floor=True` (`wire_link`: support plane is its y=-1) | `test_library.py::test_floor_false_writes_nothing_at_or_below_the_support_plane` (all parts and variants), `..._is_floor_true_minus_the_plane`, `..._work_on_an_external_floor` |
| `wire_path` wrote onto cells fixed by the task | `avoid=` (cells / boxes), `start_exclusive`, `end_exclusive`, `box=` | `test_builder.py::test_wire_path_avoid_*`, `..._box_*` |
| supports below y=1 although the floor exists | `floor_exists=True`, `floor_y=` (supports at or below it are skipped; with `box` the error even hints at it) | `test_wire_path_floor_exists_*` |
| climbing off a lever produced a diagonal dust step | an end cell that is a component forces one flat dust cell next to it; too few steps -> error | `test_wire_path_from_a_lever_or_to_a_lamp_never_climbs_diagonally_off_the_component`, physics fact `wire_path_flat_start_climbs` (lamp lights) |
| repeater on a junction killed the branch | repeaters skip turns, climbs, cells next to foreign dust/repeater/comparator and `taps=` | `test_wire_path_repeater_never_goes_on_a_junction_a_turn_or_a_tap`, fact `wire_path_branch_keeps_repeater_off_the_junction` |
| overwrote other blocks silently | atomic plan, `BuilderError` with every coordinate, nothing written | `test_wire_path_overwriting_another_block_is_an_error_*`, `..._error_lists_every_conflict_*` |
| (extra) nets shorting silently | `check_spacing=True`; `zfirst=True` to arrive along the port axis | `test_wire_path_check_spacing_*`, `test_wire_path_zfirst_*` |
| documentation gaps | sandbox facts, support rules, lever/dust/torch/lamp rules, door/piston-head semantics in `evaluation/prompts/builder_system.md` ("Redstone gotchas verified in the simulator") and docs/BUILDER.md | `tests/env/test_physics_facts.py` (31 tests) |

Backwards compatibility: all 12 stored T3 references recompile to **identical** block lists (`test_t3_references_compile_to_the_stored_solutions_after_the_wire_path_upgrade`); `tests/env/test_library.py` + `tests/env/test_t3.py` passed (196 tests) after the change; the T3 JSONs were not rewritten.

## Physics facts verified in the simulator (`scripts/t4_physics_facts.py`)

17 scenarios, each run in Nucleation **and** in the vanilla oracle (identical readings, `python scripts/t4_physics_facts.py --oracle` -> 17/17); the Nucleation side is asserted by `tests/env/test_physics_facts.py`, the vanilla side by `test_all_facts_agree_with_vanilla_26_2` when the oracle is installed.

| id | fact |
|---|---|
| `lever_adjacent_dust` | a lever powers the dust next to it on every horizontal side (15, then 14 per cell) |
| `lever_attached_block` | a lever powers the block it is mounted on, that block powers the lamp / dust next to it; dust next to the lever is powered |
| `lever_no_diagonal` | dust one level up diagonally from a lever gets 0; flat dust first then up works (15, 14, 13) |
| `dust_line_end` | a straight line powers the block at its end, not the cells beside the middle |
| `dust_stub` | a dust with one connection also points at the opposite side |
| `dust_corner` | a corner dust powers only the blocks its two connections point at |
| `dust_powers_block_below` | dust powers the block it sits on (a lamp next to the floor block under it lights) |
| `lamp_conducts` | **a redstone lamp is a conductor**: lamps / dust next to a lamp pointed at by dust light too |
| `stone_conducts` | same for stone |
| `torch_powers_adjacent_dust` | wall and floor torches power adjacent dust on every side (15, 14) |
| `torch_inverts_its_block` | power in the mounting block switches the torch off; its dust drops to 0 |
| `repeater_input_is_behind` | dust beside a repeater does nothing; dust behind works |
| `dust_step_up` | a step up works unless a conductor sits above the lower dust |
| `step_down_over_stone` / `step_down_over_slab_is_dead` | stepping down carries over a stone block but not over a top slab |
| `wire_path_flat_start_climbs` / `wire_path_branch_keeps_repeater_off_the_junction` | the two `wire_path` guarantees above, in the simulator |
| `hop_on_top_slabs_does_not_leak_z_into_x` and `..._x_into_z` / `hop_on_full_blocks_leaks` | crossing by hopping on top slabs is isolated both ways; the same hop on full blocks leaks |

Sandbox and support facts (also tests): nested defs / lambdas / module-level helpers / comprehensions / `functools.reduce/partial` are allowed; classes, `getattr`, underscore attributes, bare `except`, other imports are not. Plain blocks, lamps, pistons need no support; dust, repeaters, comparators, torches, levers do; only a *top* slab holds them. Nucleation does not pop unsupported parts (vanilla would); `env.blocks.floating` is the checker. `moving_piston`/`piston_head` are non-air ("solid" region mode reads 1), which the validity audit used to change the door ports to `block_in` + `air` (`init` = value at rest, air for a door resting open).

## Requests to env owners (nothing in `env/runner.py`, `env/contract.py`, `harness/`, `mira_mcp/`, `scripts/mira_env_cli.py`, `tools/oracle/` was edited by this work)

1. **`paste_stable` failure message** (`env/runner.py` ~line 301). Today: `inworld: 12 cells differ, e.g. [x, y, z] saved repeater -> repeater <state>`. It names one arbitrary cell (the lexicographically first) and the raw state, so an agent cannot tell what to change. Suggested text: `paste_stable FAILED: the settled at-rest world changes when it is loaded (InWorld) / placed again (Placement): 12 cells differ. First difference at [x,y,z]: a repeater that was powered=false is powered=true after loading. Typical causes: a comparator/repeater that is already powered at rest (design the REST state with every enabling input low), two observers facing each other, a torch loop. Cells: ...` - i.e. (a) name the mode in plain words, (b) print the changed *property* (`powered=false -> true`), not the whole state, (c) list up to 5 differing cells grouped by block kind, (d) append the one-line rule above. Same for `never quiescent`: say which cells were still changing.
2. **`mira_mcp/session.py` line ~70 (`for d in (TASK_DIR, TASK_DIR / "t3")`) enumerates task dirs itself, so `python scripts/mira_env_cli.py tasks` / MCP `list_tasks` / `start_task` by bare id do NOT see T4 yet** (verified: 34 tasks listed). `env.task.list_task_ids()` / `load_task()` do see them (38). Fix: add `TASK_DIR / "t4"` to that tuple (and to the docstring); `start_task` with a path to `env/tasks/t4/<id>.json` already works.
3. `env/models.py` does `from env import library` so the T4 models (`addsub`) register for `env/validate_tasks.py env/tasks/t4/<id>.json`.
4. `env/contract.py::ReferenceModel.generate` still restarts the model for the hidden stream (sequential tasks therefore use timed `sequences`, not `reference_model`, in T4).
5. `tools/oracle/gametest.py`: batched jobs in one JVM can contaminate each other (finding of the validity agent). `scripts/t4_oracle.py` shards one capture per JVM by replacing `gametest.capture_many` in-process; once the driver is fixed it can use the stock one. Long captures (`t4_shift32`: 8 captures, up to 4800 ticks) are very slow in vanilla (> 40 min for the set on a loaded machine); a `--max-ticks` / sub-sampling option for sequences in `oracle_task` would help.
6. Time: gates are expensive (9 min for a 12-mutant `t4_adder16` gate, 23 min for `addsub8` at 24 mutants on a loaded machine). `ProcessPoolExecutor` per task helps only across tasks; a `fast` incremental runner (reuse the placed world, flip one block) would cut the per-mutant cost.
7. Environment quirk worth knowing: `setsid nohup ... &` background jobs were killed when the tool call returned in this sandbox (several early validations produced empty logs); run long jobs in the foreground with a long timeout.
